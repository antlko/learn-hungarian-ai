## ROUND 2 — offline bundled runtime (ADR-080, amends ADR-079 + tts part of ADR-061), 2026-11-18
User (verbatim RU): «Это должно быть установлено и так уже в бинаре проекта по дефолту. Т.е. даже если проект PyPI загнется я все равно мог бы пользоваться этой либой. Voice only in reader (confirmed).
DECISION (adviser memo): «Установить» for tts NEVER uses the network; it becomes Включить/Выключить. Per platform we vendor a python-build-standalone `cpython-3.12.x-<triple>-install_only_stripped.tar.gz` + a wheelhouse of exactly: piper-tts 1.8.0 (abi3), onnxruntime 1.32.0 (cp312; linux wheels are manylinux_2_28, macOS needs macosx_14_0_arm64), numpy (cp312), protobuf, flatbuffers, packaging, pathvalidate (no sympy/coloredlogs/humanfriendly/mpmath: verify with a real offline install). Matrix: Python 3.12 only; darwin-arm64, linux-amd64 (glibc>=2.28), linux-arm64. Unsupported (card unavailable, key errors.componentNoTtsRuntime, device voice is the floor): darwin-amd64, Windows, distroless `slim` image.
Enable steps (Go): verify sha256 of every file against services/tts/vendor/MANIFEST.sha256 -> extract python tarball (archive/tar, refuse tar-slip) -> `python/bin/python3 -I -m pip install --no-index --no-deps --require-hashes --only-binary=:all: -r requirements.lock --find-links <wheelhouse>` with env PIP_NO_INDEX=1 PIP_CONFIG_FILE=/dev/null (no venv; install into the bundled interpreter) -> write runtime.stamp (MANIFEST digest; if current, skip to start) -> start child -> child loads ALL present voices at startup (TTS_PRELOAD=all, ~455 MB RSS) -> /health ready only after load -> running -> provider=managed via updateConfig. Disable: stop child (frees memory) + provider=device (survives restart). Existing Uninstall becomes secondary «Удалить распакованную среду» (frees disk; bundle stays). tts spec gets bundled:true; claimInstall/detectPython skipped for tts; mt unchanged (keeps PyPI path). Remove tts steps venv/pip; add steps verify «Проверка файлов», unpack «Распаковка среды», voices «Голоса загружаются в память» (+ en), keys components.tts.enable|disable|freeDisk, errors.componentNoTtsRuntime|componentBundleCorrupt; ramNeed «≈450 MB, все три голоса (измерено)»; NO «скачать»/«загрузка» wording. ManagedDTO gains `bundled bool`; no new routes (enable/disable map onto install/start/stop server-side).
Layout: source of truth services/tts/vendor/ = MANIFEST.sha256 (sha256,size,path), requirements.lock (--hash lines), darwin-arm64/ linux-amd64/ linux-arm64/ (python tarball + wheels each), source/ (GPL corresponding source: piper_tts-1.8.0.tar.gz (+ espeak-ng source if the sdist lacks it)), README. `make tts-vendor` = ONLY network target (maintainer; pip download --only-binary=:all: --no-deps --platform … --python-version 3.12 + python tarballs with upstream SHA256SUMS). `make tts-verify` re-hashes offline (also in make test / docs-check). Manager finds bundle: operator flag --tts-runtime-dir / env TANULOM_TTS_RUNTIME_DIR (never route/config) -> embedded bundle if built with tag `ttsbundle` (package internal/components/ttsbundle, one file per GOOS/GOARCH, Makefile stages that platform's vendor dir + voices into a gitignored data/ dir like ensure-spa) -> else unavailable. make build / release / Docker `full` use the tag; dev+test do not (`make dev` passes --tts-runtime-dir ../services/tts/vendor). Voice resolution: --voices-dir, then embedded voices (extracted to <data>/components/tts/voices), then <data>/voices. Docker full may drop COPY langpack/voices. Binary ~300-340 MB per platform (reverses ADR-079 'Rejected (3)': user's «в бинаре» justifies it).
app.py -> stdlib ThreadingHTTPServer on 127.0.0.1 (drop fastapi/uvicorn/pydantic), same contract /health /voices /synthesize, body cap 16 KB, TTS_PRELOAD, keep espeak long-path symlink + atexit cleanup; Python unittest in the smoke test.
